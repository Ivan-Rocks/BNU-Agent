# 选型建议：概念可视化课件工作流的运行底座

日期：2026-11-02
版本：1.0
用途：为"概念 → 课程定位 → 策划 → 报告"的可复用工作流选定运行底座
关联：`../Objectives.txt`、`../策划报告.md`、本目录 `02-工作流设计.md`

## 一 要解决的问题

我们要在 BNU 教育技术实验室的 AR 课件场景里，建立一条**可复用的内容生产工作流**：

> 输入一个概念（如"卷积"）→ 在教材知识库中定位它属于哪个年级/科目 → 生成课件策划方案 → 产出一份标准化的 md 报告（概念定义 / 课程覆盖 / 可视化课件设计）。

这份工作流需要跑在某个"底座"上，让实验室成员（或未来的智能体）能反复调用。本文回答"底座选什么"。

## 二 选型标准

按重要性排序：

| 标准 | 含义 | 为什么重要 |
| --- | --- | --- |
| 可复用性 | 一次定义，反复调用，产出格式一致 | 这是"工作流"存在的根本理由 |
| 落地速度 | 今天定义、本周跑通一个概念 | 试点需要尽快看到真实产出 |
| 编排能力 | 多步骤、可审阅、可重试、可记录状态 | 策划→审阅→定稿不是一步生成 |
| 边界清晰 | RAG、知识库、报告模板与底座解耦 | 公司底座、实验室数据、个人成果边界要能分开 |
| 可迁移 | 以后能否接公司底座或独立部署 | Objectives 提到"仿 pi"与公司底座 |

## 三 三个候选方案

### 方案 A：DSH 原生（推荐）

用当前 DeepSeek Harness（DSH）作为编排底座：
- 工作流用 DSH 的 **skill（技能）+ Tool（工具）+ workflow 多智能体编排** 表达；
- 每一步是一个可单独调用的工具或技能，整体串成 pipeline；
- **RAG 引擎保持独立模块**（可以是独立脚本/服务），通过 **MCP** 暴露给 DSH；
- 知识库、报告模板、课件规格作为版本化的数据文件存在仓库里，不绑定底座。

- 优点：编排/工具/MCP/skill 现成；人已经在这个环境里；最快得到一个真实可调用的工作流；RAG 与模板完全解耦，将来可换。
- 缺点：工作流本身对 DSH 有依赖；若最终要脱离 DSH 独立部署，需要一次轻量迁移（pipeline 逻辑仍可用）。

### 方案 B：公司底座做后端 + DSH（或 pi）做前端

- 优点：直接复用公司已有 RAG 引擎、运行时、plugins；贴合 Objectives 的"底座 + RAG + runtime + plugins"愿景。
- 缺点：依赖公司底座的可达性与授权；数据/资产边界复杂（见 `../策划报告.md` 第十三章风险表）；试点阶段可能被公司边界问题拖慢。

### 方案 C：pi 式独立 harness（小核心 + 扩展）

- 优点：可移植、无外部依赖；长期可演进成自己的平台。
- 缺点：要自己实现编排、工具协议、会话管理、权限隔离（pi 本身默认没有沙箱权限系统）；最慢，与"先跑通一个概念"的目标冲突。

## 四 推荐结论

**选择方案 A，并明确两条纪律：**

1. **底座只做编排，不做领域逻辑。** RAG 检索、概念定位、报告模板、课件规格都作为"工具/数据"存在仓库里，通过固定接口（先内部函数，多调用端共享时再封装 MCP）被 DSH 调用。这样即使以后换 pi 或接公司底座，代价只是换一个"编排壳"。
2. **先跑通一个概念，再谈 syllabus 全量。** 底座的价值由"卷积"这一份报告的产出质量来证明，不由架构图证明。

### 何时升级

| 触发条件 | 升级方向 |
| --- | --- |
| 实验室有多个成员、多个调用端需要共享同一套工具 | 把内部函数封装为 MCP server（方案 A 内升级） |
| 公司底座确认可复用且边界已书面约定 | 评估切换到方案 B |
| 需要脱离 DSH 独立交付给实验室 | 迁移到方案 C（复用已解耦的工具与模板） |

## 五 底座能力映射（正常 DSH，super-agent 暂不接入）

用户已确认：**现阶段不接入 DSH 新出的 super-agent，按正常 DSH 能力实现**。经核查，正常 DSH 已提供的能力包括：

- 插件体系：Service（服务）、Event（事件）、Config（配置）、Tool（工具）；
- **skill（技能）**：可复用的任务指令集；
- **workflow**：多智能体编排（用脚本把多个子代理/阶段组织成流水线）；
- **subagent**：派生子代理处理独立子任务；
- **MCP**：连接外部工具/服务。

因此工作流的落地形态是：**一个顶层 workflow（编排）+ 若干 skill（每阶段的方法）+ 一组 Tool（RAG 检索、概念定位、报告生成）+ 一个 MCP 暴露的独立 RAG 引擎**。super-agent 作为后续候选能力，待其稳定、且本项目出现明确需求（如更重的多角色协作）时再评估接入，当前不纳入范围。

## 六 本次已确定的事（决策记录）

1. 底座选 **DSH 原生（方案 A）**；**现阶段不接入 super-agent**，按正常 DSH（skill + Tool + workflow + MCP）实现。
2. RAG 独立、经 MCP 暴露，模板与知识库版本化存放。
3. 知识库只做**公开课标 + 教材目录**的映射（知识点→年级/科目），不做页码级正文引用。
4. 工作流出口从"单条 syllabus"改为"**概念 inventory → 组课**"：零散概念先作为 prototype 进库存，再按需组装成多门课程（初高中 AI / Intro to AI / Intro to Discrete Math 等）。
5. 试点概念为"卷积"，产出见 `../reports/03-卷积可视化-Pilot报告.md`。

## 七 判断边界

"DSH 提供 MCP / workflow / subagent"来自本会话对 harness 的 inspect 结果，可信。"卷积属于大学课程、初高中课标未覆盖"来自公开课标常识与检索，具体版次、页码需在接入知识库后逐条核实。方案 B 对"公司底座"能力的假设来自 `../Objectives.txt`，尚未做接口适配验证。
